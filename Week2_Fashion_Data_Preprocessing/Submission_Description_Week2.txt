My Week 2 submission, Data Acquisition and Preprocessing Techniques for Fashion and Apparel, contains an enhanced Word report and a reproducible GitHub project. This revision directly addresses the need for real public-source evidence by adding an openly licensed fashion retail catalog alongside the original controlled apparel cleaning demonstration.

The real-data case study uses the Livostyle Women’s Fashion Catalog open-data repository under the MIT license, with its exact upstream revision and reported October 2026 snapshot date recorded for reproducibility. It processes 161 collection records and a separate hierarchical category-summary dataset reporting 2,938 unique products. The Python pipeline validates collection keys, checks duplicates, converts update timestamps into UTC, parses and cleans HTML descriptions, standardizes categorical identifiers, validates numerical counts, and records missing-field flags. It produces a clean CSV, category-share tables, a ranked collection table, an exception table, and a machine-readable audit. The recorded findings include three missing collection images, one missing SEO description, two inconsistent collection counts, and the fact that overlapping collection memberships must not be misreported as unique products or sales.

The report also documents additional appropriate public data sources, including H&M’s fashion recommendation dataset, UCI Online Retail, clothing reviews, Google Trends, Open-Meteo, and World Bank textile indicators, explaining licenses, access requirements, analytical grain and limitations. It includes an independent synthetic transaction-quality exercise to demonstrate cases absent from public catalog records, such as invalid prices, duplicate invoice lines, missing SKUs, inconsistent returns, discounts, and quarantine policies. The 163 synthetic records reconcile to 147 clean sales, two returns and 14 quarantined rows. These numbers are explicitly labeled as synthetic and are not attributed to the catalog.

The submission provides a data dictionary, quality rules, cleaning methodology, transformations, feature engineering, versioned source references, recommended cross-source join keys, governance considerations, worked examples, source-specific limitations, and a one-week implementation plan. The included code can be run without private company access, with source snapshots bundled locally and optional pinned downloads. All 21 automated tests were executed successfully. Finally, the README and an evaluator-first guide link directly to the Word report, original data, scripts, quality audits and processed outputs, making the work independently checkable.
