I am submitting my Week 2 assignment, “Data Acquisition and Preprocessing Techniques for Fashion and Apparel,” for the Junior Data Science Analyst Internship. The submission consists of a structured Word report and a complete GitHub technical project with reproducible source code, sample input data, cleaned outputs, documentation, an execution notebook and automated tests. Its purpose is to demonstrate how a junior analyst can collect suitable public information, document the origin and limitations of data, clean imperfect transaction records, and produce analysis-ready datasets using transparent business rules.

The report reviews several authoritative research sources relevant to apparel, consumer behaviour and textiles. These include the H&M Personalized Fashion Recommendations dataset, UCI Online Retail, Google Trends, Open-Meteo weather data, Indian government textile production records, World Bank textile indicators and Open Supply Hub. It distinguishes fashion-specific data from general retail or macroeconomic sources, describes access and licensing requirements, and explains why some sources should not be combined directly. Restricted datasets are not represented as downloaded or analysed.

A major contribution is a working Python preprocessing pipeline built with pandas. The project generates a deliberately messy synthetic fashion-order dataset, including incomplete values, inconsistent apparel sizes, duplicate order lines, cancellation/return cases, invalid prices and dates, and inconsistent discount formats. The pipeline standardizes categories and sizes, parses numeric values, checks business constraints, separates valid returns, quarantines problematic rows with reason codes, and creates weekly and customer-level analytical features while avoiding future-data leakage.

The executed demonstration processes 163 synthetic input rows into 147 cleaned sales records, two valid return records and 14 quarantined records. It retains 149 records for controlled analysis, achieves complete row-count reconciliation, and records 11 passing automated tests. Source-file SHA-256 checksums, quality metrics, reusable code, cleaned CSV files and a visual outcome chart allow the evaluator to verify these findings directly. All transaction-level amounts and outcomes are explicitly synthetic rather than claims about an actual employer or customers.

Finally, the report includes a five-day implementation plan, a data dictionary, policies for missing values and duplicates, acceptance criteria, and a reflection on source bias, privacy, time zones, currency conversion, return handling and external dataset access. The methodology can be reproduced offline without internal company resources.
