I am submitting my Week 5 assignment, “Data Quality Assessment and Error Handling in Apparel Data,” as a detailed Word report with a reproducible Python project. The report uses two explicitly different evidence sources: an intentionally messy synthetic apparel transaction dataset for demonstrating error handling and a real publicly published U.S. clothing-store monthly sales series from the U.S. Census Bureau via FRED. I keep these sources separate so the evaluator can distinguish controlled demonstrations from observed industry statistics.

The report establishes measurable definitions and example release thresholds for completeness, validity, consistency, uniqueness, integrity, timeliness and accuracy. It specifically explains why automated validation alone does not establish factual accuracy, which would require comparison with independently trusted price books, stock counts or accounting records. The synthetic stress test starts with 163 apparel order lines. The audited pipeline outputs 147 accepted sales lines, two valid return lines and 14 quarantined records, reconciling all input rows. It standardizes size names, product categories, timestamps, currency-formatted prices and discount formats such as 10, 10%, and 0.10. The report explains why missing financial values are quarantined rather than invented, why guest customer IDs are excluded from identified-customer profiles, and why return quantities are separated from sales demand.

The independently observed public-series check covers 92 consecutive monthly clothing-store sales observations from January 2019 to August 2026. It verifies chronological continuity, date uniqueness, positive target values and source vintage. Sixteen unusually large year-over-year movements are flagged for review rather than automatically deleted, since real economic disruptions such as the 2020 pandemic can be meaningful observations. Three original charts show row reconciliation, quarantine reasons and public-data anomaly screening.

The report also contains detailed issue-by-issue corrections, responsible business roles, phased validation gates, a release checklist, incident escalation rules, source limitations, privacy considerations and reproducibility instructions. The GitHub project includes both input datasets, complete Python scripts, clean and quarantined outputs, a documented evidence JSON file, charts and automated tests. All 10 tests pass on the supplied datasets. No employer data or measured company financial improvements are claimed.
